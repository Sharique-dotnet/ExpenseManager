# Expense Manager

A deliberately minimal Android expense tracker in Indian Rupees. Add an item and an amount, see today's list with a pinned daily total, and browse a monthly calendar of daily totals.

Flutter · Dart · Riverpod · Firebase Authentication · Cloud Firestore. Visual design follows the Nook design system (`DesignSystem.jpg`): Moss/Mint palette, Inter, 16 px card radius, 4/8/12/16/24 spacing.

## Features

- Email/password sign-up and sign-in; each user's data is private.
- **Today**: today's expenses (newest first) with time, and a total pinned above the bottom navigation.
- **Add / edit**: item, amount (₹, up to 2 decimals), date (today or earlier), time (never later than now). Delete asks for confirmation.
- **Calendar**: Monday-first month grid, each day with expenses shows its total in green (`₹120`, `₹1.2k`, `₹3.4L`); tap a date for its full list and exact total. Future dates can't be opened.
- Works offline: writes are kept on the device and marked "Syncing" until Firestore confirms them.

Out of scope by design: categories, budgets, income, charts, exports, multiple currencies.

## Data model

```text
users/{uid}/expenses/{expenseId}
  itemName:    string     1–60 chars, trimmed
  amountPaise: int        1 … 100000000 (₹0.01 … ₹10,00,000.00)
  occurredAt:  timestamp  when it happened (user-picked local date + time)
  localDate:   int        that local calendar date as yyyymmdd, e.g. 20261028
  paymentType: string     cash | upi | bank_transfer (required on writes; older records may lack it and show "Not specified")
  createdAt:   timestamp  server time
  updatedAt:   timestamp  server time
```

- Money is stored and summed as integer **paise**; it is converted to rupees only for display.
- Totals are never stored; they are computed from the records.
- `localDate` is the date the user chose. Lists, totals and the calendar query and group by it, so an expense stays on its day even if the phone's timezone changes later. Times are shown in the phone's current timezone.
- One range query per screen: a day (`localDate == d`) or a month (`localDate` between the 1st and the last day). These use Firestore's automatic single-field index; `firestore.indexes.json` needs no composite indexes.

### Security rules

`firestore.rules` allows a signed-in user to read and write only `users/{their uid}/expenses/*`, and on every create/update checks: exactly the six fields above, types, name length, amount range, `createdAt`/`updatedAt` set to server time (and `createdAt` unchanged on edit), and no future dates.

Limitation: rules only know UTC. They reject `occurredAt` more than 10 minutes after server time (allowing for clock drift) and a `localDate` later than today's date anywhere on Earth (UTC+14). They don't cross-check that `localDate` matches `occurredAt`; the app always writes them together, and a mismatch could only affect the user's own data.

## Setup

Requirements: Flutter (stable, Dart 3.13+), Android SDK, Node.js 18+, Java 21 (for the Firebase emulators).

```bash
flutter pub get
```

### Option A: run against local emulators (no Firebase account)

```bash
cp tool/firebase_options.placeholder.dart lib/firebase_options.dart   # only if the file doesn't exist
cd firestore-tests && npm install && npm run emulators                 # Auth :9099, Firestore :8080
```

Android emulator (reaches the host at 10.0.2.2):

```bash
flutter run --dart-define=USE_FIREBASE_EMULATOR=true
```

Physical phone over USB:

```bash
adb reverse tcp:8080 tcp:8080
```

```bash
adb reverse tcp:9099 tcp:9099
```

```bash
flutter run --dart-define=USE_FIREBASE_EMULATOR=true --dart-define=FIREBASE_EMULATOR_HOST=127.0.0.1
```

Create an account on the sign-up screen; emulator accounts and data are wiped when the emulators stop. The app passes `automaticHostMapping: false`, so `127.0.0.1` reaches the host through `adb reverse` instead of being rewritten to the emulator-only `10.0.2.2`.

### Option B: connect a real Firebase project (manual steps)

1. In the [Firebase console](https://console.firebase.google.com), create a project.
2. **Authentication → Sign-in method**: enable **Email/Password**.
3. **Firestore Database**: create a database in production mode (pick a region near your users, e.g. `asia-south1`).
4. Install the CLIs and log in:

   ```bash
   npm install -g firebase-tools
   ```

   ```bash
   dart pub global activate flutterfire_cli
   ```

   ```bash
   firebase login
   ```

5. From the project root, generate the client config (writes `lib/firebase_options.dart`, both gitignored along with `google-services.json`). Select only Android:

   ```bash
   flutterfire configure --platforms=android --android-package-name=com.eptatechnologies.expense_manager
   ```

   `flutterfire configure` also adds the `google-services` Gradle plugin and writes your project/app IDs into `firebase.json`. Discard both (`git checkout -- firebase.json android/`): the app initialises Firebase from `lib/firebase_options.dart`, so builds don't need the gitignored `google-services.json`.

6. Deploy the security rules and indexes:

   ```bash
   firebase deploy --only firestore:rules,firestore:indexes --project <your-project-id>
   ```

7. Run on a device:

   ```bash
   flutter run
   ```

Firebase client config identifies your project but is not a secret; access is enforced by the security rules. It is still kept out of git here.

## Release APK

1. Create an upload keystore (keep it and its passwords out of git):

   ```bash
   keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```

2. Add `android/key.properties` (gitignore it) and point `signingConfigs` in `android/app/build.gradle.kts` at it, replacing the debug signing config. See <https://docs.flutter.dev/deployment/android#sign-the-app>.
3. Build:

   ```bash
   flutter build apk --release
   ```

   Output: `build/app/outputs/flutter-apk/app-release.apk`. For Play Store uploads use `flutter build appbundle`.

Until step 2 is done, release builds are signed with the debug key and are only suitable for testing.
